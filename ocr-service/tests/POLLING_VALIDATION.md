# OCR timeout regression fix — 13 October 2026

The supplied log shows 130.421 seconds for quotation -2.pdf. The frontend aborted at 90 seconds without stopping backend inference; the next request was rejected after a 10-second engine-lock wait. The earlier timeout change caused this regression. Decode was 5.218 seconds and final recognition 44.235 seconds, leaving about 81 seconds in orientation/model initialization and other work before recognition.

Fixes: remove only ScanModal's extra LoadingDialog; keep its existing inline progress. Replace the web app's synchronous upload with authenticated job submission/polling. Duplicate file/dpi/type submissions reuse the same active/completed job for the same verified user. One worker executes jobs; two can be outstanding, so a second normal upload queues instead of hitting the removed 10-second lock timeout. Cancel/close sends DELETE and cancellation is checked between inference stages and during lock waits. A current ONNX call finishes before the engine is released. Backend budget is 300 seconds, FE terminal polling budget 330 seconds. In-memory jobs require one Uvicorn worker and a backend restart before the new frontend is used. Existing /ocr remains available.

Speed: one reduced-size detection chooses the text axis, and up to eight crops in two directions choose upright orientation. Full OCR shares unfiltered detection/cropping/classification across both language recognizers, preserving Japanese-only readings. Per-stage timings are logged.

Local measurements (single runs; load differs from the supplied production log): direct OCR took 15.782 seconds for -1.pdf, including cold engine initialization, and 11.343 seconds for -2.pdf. Both retained expected order/drawing/product/qty/price/net/process/date values. See polling-validation-results.json.

Real OCR through TestClient job HTTP endpoints: -1.pdf accepted in 47ms and finished/polled in 30.016s. -2.pdf accepted in 16ms while the first ran, queued, then finished/polled in 44.187s from its own submission. Duplicate POSTs returned the same job IDs, without duplicate inference or 429. Camera image #4 accepted in 16ms and finished in 18.500s, with Shinwa master names/codes and main fields correct. Address OCR still needs review. See job-api-validation-results.json. These include model initialization, queue/poll timing and concurrent local load, not a production-network guarantee.

Validation: 47 frontend tests, 28 backend tests, TypeScript and production build passed. Coverage includes job ACK/poll/result, deduplication, queueing, cancellation/capacity release, owner isolation, deadlines, transient polling network failure, bounded admission, shared raw detections and actual PDF/camera field assertions. Physical tablet/live gateway testing remains outstanding.
